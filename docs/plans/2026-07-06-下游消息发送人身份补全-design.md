# 下游消息发送人身份补全（名字 + 头像）设计

> 日期：2026-07-06
> 分支：`rewrite/v2`
> 背景：下游 forwarder 核心闭环已打通（queue → `receiveMessage` → ACK 判定 → 重试/熔断/死信/断点）。但转发的 `data` 是 WeFlow 原始消息，发送人只有 `senderUsername`（wxid），**没有微信名和头像**，下游落工单后无法正常显示发言人。本设计定义如何从 WeFlow 补全发送人身份并送达下游。

> - 下游契约（群同步）：[docs/weflow-群组放行同步接口对接文档.md](../weflow-群组放行同步接口对接文档.md)（syncGroups）

## 1. 范围

**本期**：给转发信封补一个顶层 `sender: { username, name, avatar }`（发送人身份），并顺带用已有 syncGroups 把**群名/群头像**推给下游（填充一直空置的 `SyncGroupsRequest.avatarUrl`）。

**不做**：不新建成员目录表（用内存映射，见 D4）；撤回事件 `message.revoke` 的 sender 暂不补（见 §7）；媒体消息身份补全随媒体链路二期再说。

---

## 2. 现状与缺口

| 维度 | 现状 | 缺口（本期补） |
|------|------|----------------|
| 消息正文 | `fetchMessagesPage` 拉非 chatlab 消息，原样透传成 `data` ✅ | — |
| 发送人身份 | `data.senderUsername` 只有 wxid | **补 name + avatar，放信封顶层 `sender`** |
| 群名 | syncGroups 推 `groupName` ✅ | 用 chatlab `meta.name` 刷新 |
| 群头像 | `chat_group.avatar_url`、`SyncGroupsRequest.avatarUrl` **一直是空占位** | **用 chatlab `meta.groupAvatar` 填充并推下游** |
| queue 落库 | 无身份列 | **加 `sender_name`/`sender_avatar`** |

---

## 3. 数据来源：`/api/v1/messages?chatlab=1`

关键发现：WeFlow 文档化 API 里唯一的头像来源是 **ChatLab 格式**。同一 messages 接口带 `chatlab=1` 时返回：

```jsonc
{
  "meta": {
    "name": "zhizhuIP服务对接群-…",           // 群名
    "groupId": "44482854010@chatroom",
    "groupAvatar": "https://wx.qlogo.cn/mmcrhead/…/0",  // 群头像
    "ownerId": "wxid_…"
  },
  "members": [
    { "platformId": "wxid_9p74510ujg1g22", "accountName": "无心",
      "avatar": "https://wx.qlogo.cn/mmhead/ver_1/…/0" }
    // platformId=群 ID 那条对应系统消息的「发送人=群自己」
  ],
  "messages": [ /* ⚠️ 精简过、缺关键字段，不可用 */ ]
}
```

**两个硬约束（决定整体形态）：**

1. **必须发两次请求**：chatlab 的 `messages` 精简、缺字段，**正文仍走非 chatlab 的 `fetchMessagesPage`**，身份另走一次 `chatlab=1` 只取 `meta` + `members`。
2. **`members[]` 只含「本次返回消息里出现过的成员」**：取身份的 chatlab 请求窗口，必须覆盖到要落库那批消息的发送人，否则该人身份缺失（降级为 null）。→ 取身份与取正文**同窗口成对发**（同 `talker/start/offset/limit`），保证这一页的发送人都能在 members 里查到。

---

## 4. 关键决策摘要

| # | 决策 | 理由 |
|---|------|------|
| D1 | **身份放信封顶层 `sender`，`data` 保持原样透传** | 不破坏 receiveMessage「`data` 不增删字段」契约；与当初把 `sessionId` 加到顶层同一手法；下游直接读、无需 join |
| D2 | **发送人 = 逐条快照；群 = 慢变目录** | 发送人身份随消息走（信封 sender）；群名/群头像走已有 syncGroups 目录，天然分层，各取所长 |
| D3 | **补全时机在同步落库侧（syncService），存进 queue 新列** | forwarder 不必回连 WeFlow，职责干净；身份在入队时快照，转发时直接读列 |
| D4 | **成员映射用内存、按同步轮次，不建成员表** | 内部工具优先简单；代价仅「实时每次多发一个本机 chatlab 请求」，localhost 开销可忽略。持久化成员目录表留作后续优化 |
| D5 | **群头像最终一致**：首轮 syncGroups 可能还没拉到头像，下一轮补 | 时序上 syncGroups 在消息拉取之前；头像随后落 `chat_group` 再推，可接受 |
| D6 | **未解析到身份 → name/avatar 存 null** | 非好友/系统消息/窗口未覆盖等，下游用首字+色块兜底占位；best-effort 不阻塞转发 |

## 5. 架构与数据流

```
同步/实时拉取（syncService）
  ├─ fetchMessagesPage(talker, …)           非 chatlab → 正文 messages（= data）
  └─ fetchMembers(talker, 同窗口)           chatlab=1  → meta + members 映射
        │
        ├─ 并入「本会话内存映射」 memberMap: wxid → { name, avatar }
        ├─ upsert chat_group（group_name / avatar_url ← meta.name / meta.groupAvatar）
        └─ ingestOne 按 senderUsername 查 memberMap → queue.sender_name / sender_avatar
                                                            │
下游转发（forwarder）                                        │
  claimNext 带出 sender_name/sender_avatar ────────────────┘
        └─ 拼信封 { event, sessionId, sender:{username,name,avatar}, data }

群同步（groupSyncService）
  组 SyncGroupsRequest 时把 chat_group.avatar_url 带进 avatarUrl 推给下游
```

## 6. 分文件改动

### 6.1 `server/src/weflow/restClient.ts`
- 新增 `fetchMembers(talker, start, offset, limit, end?)`：打 `/api/v1/messages`，参数在现有基础上加 `chatlab: 1`。解析响应的 `meta`（`name`/`groupAvatar`）与 `members[]`（`platformId`→`{accountName, avatar}`），**忽略 `messages`**。返回 `{ groupName, groupAvatar, members: Map<string,{name,avatar}> }`。宽松取字段，缺失为 null。
- `fetch→json` 顺序依赖，沿用 async/await（与现有方法一致）。

### 6.2 `server/src/db/schema.ts`（迁移 v5 → v6）
- `SCHEMA_VERSION` 5 → 6。
- queue 加 `sender_name TEXT`、`sender_avatar TEXT`（可空）。
- 迁移分支照现有「查 `table_info(queue)` 有无该列，无则 `ALTER TABLE queue ADD COLUMN`」的自愈写法补两列（DDL 里同步补列定义，全新库由 DDL 带出）。

### 6.3 `server/src/db/queue.ts`
- `EnqueueInput` 加 `senderName: string | null`、`senderAvatar: string | null`；`insertStmt` 列 + 占位补上。
- `ClaimedMessage` 加 `senderName`/`senderAvatar`；`pickStmt` SELECT 补两列、`claimNext` 映射带出。

### 6.4 `server/src/sync/syncService.ts`
- `pullSession`/`pullRealtime`：每翻一页正文，配一次**同窗口** `fetchMembers`，得到该页的 `members` 映射 + `meta`。**逐页即用、不跨页累积**（每页 members 已覆盖该页发送人，D3/§10-3 已确认无需跨页 union 校验）。
- 每页顺手 upsert `chat_group`（`group_name`/`avatar_url` ← `meta.name`/`meta.groupAvatar`）；幂等 COALESCE，重复 upsert 无害。
- `ingestOne`：按 `n.senderId`（=senderUsername）查该页 members，把 `senderName`/`senderAvatar` 传进 `queue.enqueue`。查不到传 null。
- 单页 chatlab 请求失败**不影响正文落库**：`try/catch` 吞掉、该页身份降级为 null（best-effort，与既有「实时回查失败仅记日志」的错误隔离一致）。

### 6.5 `server/src/downstream/client.ts`
- `ReceiveEnvelope` 加可选 `sender?: { username: string | null, name: string | null, avatar: string | null }`。
- （`SyncGroupsRequest.avatarUrl` 已存在，无需改类型。）

### 6.6 `server/src/downstream/forwarder.ts`
- `processOne` 拼信封时加 `sender`，字段取自 `ClaimedMessage.senderName/senderAvatar` + `msg` 的发送人（sender_id 已随 claim 带出）。`data` 不变。

### 6.7 `server/src/sync/groupSyncService.ts`
- 组 `SyncGroupsRequest.groups[]` 时，`avatarUrl` 从 `chat_group.avatar_url` 带上（`chatGroup.listAll`/`upsertSeen` 已含该列）。

## 7. 边界与降级

| 情况 | 处理 |
|------|------|
| 发送人不在 members（非好友/窗口未覆盖） | `sender.name/avatar = null`，下游占位兜底 |
| 系统消息（type 80，发送人=群自己） | members 里 `platformId=群 ID` 那条给出群名+群头像，自然命中 |
| 撤回事件 `message.revoke` | v1 `sender` 仍为 null —— 撤回靠下游按 `data.serverId` 定位原消息，不依赖 sender 展示 |
| chatlab 请求失败 | 该页身份降级 null，不阻断正文落库/转发 |
| 实时 SSE 拉取 | 走同一套；刚说话的人必在 members，能解析 |
| `avatar` 为 WeChat CDN URL | 直接透传给下游；是否代理/缓存由下游决定，本期不代理 |

## 8. 契约变更（对接文档）

- **receiveMessage 文档 §4**：信封新增顶层 `sender` 字段（照 `sessionId` 的加法补一行字段说明 + 更新请求示例）。强调 `data` 仍原样透传、`sender` 是信封层补充元数据、`name/avatar` 可能为 null，下游需容忍缺省并做占位。
- **syncGroups 文档**：标注 `avatarUrl` 现已启用（群头像，可空），来源为 WeFlow ChatLab `meta.groupAvatar`。

## 10. 已确认（2026-07-06 定）

| 项 | 结论 |
|----|------|
| `sender.username` | **保留、不视为冗余**。下游统一读 `sender.*`，等于 `data.senderUsername` |
| 头像 URL 时效 | **下游业务，本期只透传**。`wx.qlogo.cn` 链接是否代理/缓存由下游决定 |
| 大回灌窗口 members 覆盖 | **不需要跨页 union 校验**。每页成对发 `fetchMembers`，逐页即用已覆盖该页发送人 |
